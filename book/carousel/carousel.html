Stage 01 · Define

"Improve the
dashboard" is a trap.

Vague ✕
  • "Fix the bug"
  • "Make it better"
  • "Add rejected status"
Clear ✓
  • Objective · outcome
  • Scope · which files
  • Done · a checkable list
  • Rules · what NOT to change

If a stranger took your instruction literally — would you be happy?

Stage 04 · Boundaries

The half
everyone forgets.

Change
  • Applications list page
  • Its stylesheet
Do NOT change
  • Sign-in / auth
  • Database schema
  • The Add Application form
  • Anything not listed
Paste this in every task
"If you believe another file must change, STOP and tell me — do not change it yourself."

Stages 07 – 08 · Review + Learn

Never ship a
change you didn't read.

Review the diff
  • What changed?
  • Why?
  • Anything unrelated?
  • Simpler than needed?
  • Unexpected files?
  • Actually solves it?
Turn surprise into rule
  • Notice the mistake
  • Write the rule
  • Save it in project memory
  • Never happens again

Your project should get easier to work with over time — not harder.
